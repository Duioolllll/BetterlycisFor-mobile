# 0.1.1 가사·싱크·커버 수정

[← 전체 변경 기록 / All records](README.md) · [현재 다운로드 / Current download](https://github.com/Duioolllll/BetterlycisFor-mobile/releases/latest)

## 확인한 원인

1. 기존 자동 선택 기준은 합산 점수 60점이었습니다. 제목이 달라도 가수·앨범·곡 길이만 같으면 70점이 되어 다른 노래를 채택할 수 있었습니다. 짧은 한국어 제목, 한글·영문 별칭, 다른 녹음 버전에 대한 별도 검증도 없었습니다.
2. 순차 검색이 LRCLIB의 텍스트 가사만 있어도 멈췄으며, 동기화 여부를 후보 우선순위에 반영하지 않았습니다. 잘못 선택된 결과가 캐시에 계속 남았습니다.
3. 곡 커버는 곡 식별자가 바뀌는 순간의 Bitmap만 읽었습니다. 곡 정보 뒤에 도착하는 이미지 갱신, ART_URI 계열과 알림의 큰 아이콘은 놓쳤습니다.
4. 시간 보정은 모든 곡에 공유되었고, 화면에 전달된 재생 위치의 전달 지연을 계산하지 않았습니다.
5. YRC 본문의 일반 괄호를 타이밍 태그 경계로 잘못 해석해 일부 한국어 가사 문자열을 잘랐습니다.

## 수정

제목·가수·버전·곡 길이를 독립 검증하고 Unicode NFKC 및 실제 제공처의 한글/영문 별칭을 사용합니다. 짧은 제목·가수 이름은 다른 문자열을 유사도만으로 동일시하지 않습니다. 가사의 시간 정보·한국어 원문을 비교하고, 원문 LRC가 있을 때 음역 YRC나 불가능한 시간표로 덮지 않습니다. 온라인 예전 캐시는 자동 재조회하며 새 수동 선택과 기존 로컬 가사는 보존합니다.

커버는 같은 곡의 후속 메타데이터에서도 갱신하고 Bitmap, content/HTTPS URI, 일치하는 미디어 세션 알림의 큰 아이콘 순으로 사용할 수 있는 소스를 시도합니다. 크기 제한·축소·곡 전환 시 오래된 결과 폐기를 적용했습니다. 웹에는 이미지 데이터만 전달합니다.

보정값은 곡별로 저장하며 미디어 재생 위치의 샘플 시각을 바탕으로 화면 전달 지연을 보정합니다. 커버나 설정만 갱신되는 경우의 재생 위치 되감기도 막습니다.

## 확인 범위

총 118개 파서·매칭·저장소 회귀 검증과 3개 화면 크기의 브라우저 검사를 통과했습니다. 세 곡의 실제 온라인 가사 검색도 확인했습니다. 휴대폰의 실제 재생 소리와 가사 싱크, 이미지 권한·전달 방식은 기기에서 추가 확인해야 합니다.
